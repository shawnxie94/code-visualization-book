# 《Code Visualization》目录

本目录按“原理先行，再推进到 AI 时代应用”的思路设计。传统工程场景只保留最核心的 3 个，用来承接原理并引出 AI 时代应用；性能、安全、质量、精准测试等内容不单独铺成主线，而是在影响面验证、Review 证据和系统治理中作为子能力出现。

## 全书定位

代码可视化不是简单画图，而是一套软件理解方法。它通过源码结构化、程序分析、运行时观测、变更分析和图谱建模，把代码系统转化为可观察、可查询、可验证的结构化事实。

在 AI 时代，这些结构化事实会进一步成为 AI Agent 的上下文、Review 的证据层、影响面分析的基础和系统治理的抓手。

## 目录设计原则

1. 先讲原理：读者要先理解代码数据从哪里来。
2. 再讲图谱：把 AST、调用图、Trace、变更历史等事实组织成可查询模型。
3. 只保留核心工程场景：代码库理解、变更影响分析、架构理解与遗留系统改造。
4. 最后讲 AI 新应用：Agent 上下文、代码图谱查询、AI Review 证据、AI 辅助重构。
5. 实践项目做闭环：采集、建图、分析、可视化、Agent 查询、验证报告。

## 第一篇：代码可视化的目标与边界

### 01 为什么需要代码可视化

- 大型代码库的复杂性来源
- 文档、搜索和人工经验的局限
- 代码关系、运行路径和变更历史为什么不可见
- AI 生成代码后，理解和验证压力为什么进一步上升

### 02 代码可视化到底可视化什么

- 结构：文件、模块、类、函数、变量、配置
- 关系：依赖、调用、继承、实现、引用、读写
- 行为：控制流、数据流、运行时链路、性能热点
- 演进：变更历史、缺陷、测试覆盖、变更耦合
- 组织：Owner、团队、服务目录、架构边界

### 03 从图形展示到软件理解系统

- 代码可视化不是简单画图
- 数据采集层
- 程序分析层
- 图谱建模层
- 可视化与查询层
- 工程集成层：IDE、CI、PR、测试、APM、AI Agent
