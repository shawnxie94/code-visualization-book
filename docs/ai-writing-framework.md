# AI 写作与资料收集框架

本文档用于指导《Code Visualization》新版内容写作。当前正式目录以 [`book-outline.md`](book-outline.md) 为准，调研背景见 [`research-ai-code-visualization-2026.md`](research-ai-code-visualization-2026.md)。

## 1. 写作目标

新版写作目标不是补齐传统代码可视化工具清单，而是完成一条清晰主线：

```text
原理 -> 图谱 -> 核心工程场景 -> AI 时代新应用 -> 实践闭环
```

每章都要回答：

1. 这个主题解决什么代码理解问题？
2. 需要采集哪些数据？
3. 如何分析和建模？
4. 如何可视化或查询？
5. 在 AI 时代如何服务 Agent、Review 或验证？
6. 有哪些误差、边界和局限？

## 2. 资料收集分层

后续资料不要按“看到一篇文章就塞进章节”的方式收集，而要按数据层和用途归档。

| 数据层 | 收集对象 | 典型来源 | 用途 |
| --- | --- | --- | --- |
| 源码结构层 | AST、符号、类型、继承、引用 | 编译器文档、Parser 工具、语言服务文档 | 支撑源码结构化原理 |
| 程序分析层 | CFG、DFG、Call Graph、复杂度、依赖 | 静态分析工具、论文、开源实现 | 支撑静态分析和代码图谱 |
| 运行时层 | Trace、日志、Profile、Coverage、运行时调用 | OpenTelemetry、APM、Profiler、测试覆盖率工具 | 支撑动态分析和验证证据 |
| 变更演进层 | Git diff、commit、PR、缺陷、测试历史 | Git 仓库、CI、代码评审系统 | 支撑影响面分析和风险判断 |
| 图谱表达层 | 节点、边、属性、图查询、可视化交互 | 图数据库、可视化工具、工程实践 | 支撑代码图谱和可视化表达 |
| AI 上下文层 | RAG、代码图谱、MCP、Agent 查询轨迹、Review 反馈 | AI 工具文档、论文、Agent 实践 | 支撑 AI 时代新应用 |

## 3. 标准资料卡

每条资料建议记录为一张资料卡，后续可以放到 `docs/research-cards/`。

```markdown
## 资料标题

- 来源链接：
- 来源类型：官方文档 / 论文 / 书籍 / 开源仓库 / 技术博客 / 产品文档 / 课程
- 可信度：高 / 中 / 低
- 更新时间：
- 适用章节：
- 对应问题：
- 使用的数据：AST / CFG / DFG / Call Graph / Trace / Coverage / Git Diff / Metrics / 其他
- 分析方法：
- 可视化或查询方式：
- 关键结论：
- 可复现实验：
- 可引用图表：
- 局限性：
- 待核查点：
```

## 4. 章节 Brief 模板

每章开始写作前，先写一个 brief，避免 AI 初稿跑偏。

```markdown
# 章节 Brief

## 本章要解决的问题

## 读者读完应获得什么能力

## 本章不讲什么

## 必须覆盖的概念

## 必须引用的资料卡

## 必须包含的例子

## 必须包含的图

## AI 时代关联点

## 容易误导读者的点

## 初稿验收标准
```

## 5. AI 初稿 Prompt 模板

```text
你正在为一本中文技术电子书撰写章节，书名是《Code Visualization》。

章节主题：{章节主题}
目录位置：{第几篇第几章}
读者：有工程经验，了解基本编程，但不一定系统学过编译原理和程序分析。
写作目标：解释清楚这个主题如何服务代码理解、代码图谱和 AI 时代的软件工程应用。

请基于以下资料卡写作：
{资料卡}

要求：
1. 先从工程问题切入。
2. 概念解释必须服务后续分析、可视化或 AI 应用。
3. 每个关键概念都要说明可采集的数据、可分析的问题、适合的可视化或查询方式。
4. 明确局限性、误差来源和适用边界。
5. 不要编造来源、工具能力、性能数据或案例结论。
6. 输出 Markdown。
```

## 6. 写作流程

```text
选择章节
  -> 写章节 brief
  -> 收集资料卡
  -> 生成初稿
  -> 事实校验
  -> 补图、补实验、补代码
  -> 统一术语和口吻
  -> 合并到正式章节
```

## 7. 第一轮建议

第一轮不要铺开所有章节，先写能定调的章节：

1. 01 为什么需要代码可视化
2. 02 代码可视化到底可视化什么
3. 05 从字符到 AST
4. 08 静态分析：不运行代码时能知道什么
5. 11 代码图谱：节点、边与属性
6. 16 AI 写代码之后，为什么代码理解更重要
7. 17 Agent 上下文工程

这几章写清楚后，再决定是否更新 `SUMMARY.md` 和拆分具体章节文件。
